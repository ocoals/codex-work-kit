# 2단계. 도메인 스토리 (15분)

## 목표

불편함, 해결 범위, 업무 흐름을 담은 `docs/DOMAIN.md`와 `GLOSSARY.md`가 남는다. 흐름만 담는다. 명세를 넣지 않는다. 많이 발생하는 기본 사례만 다룬다. As-Is 먼저, To-Be는 그다음. 인터뷰는 Codex가 주도하고, 전문가는 담당자이며, 나는 전달자다.

## Codex에게

터미널 B에서 실행한다. 대화는 이 터미널에서만 한다.

```
$grill-with-docs
이 프로젝트에서 개발 중인 서비스가 해결하는 현실 세계의 맥락에 대해 도메인 스토리텔링 워크숍을 한다. 너는 개발자이자 인터뷰어이고, 인터뷰를 완전히 주도해.
현실 세계를 아는 도메인 전문가는 업무 담당자다. 나는 네 질문을 담당자에게 전달하고 답을 INTERVIEW.md에 원문으로 붙인다. 내 판단을 담당자 답으로 취급하지 마.
담당자는 도메인 전문가일 뿐 개발은 전혀 모른다고 가정하고 현장 말로 물어. 이 인터뷰는 공동 이해를 높이고 GLOSSARY.md 등을 만드는 용도로만 한다. 설계와 구현 얘기는 하지 마.

이 문서의 쓰임: 현실의 불편함 설명, 해결할 것과 안 할 것의 구분, 유저스토리와 기능 목록의 근거, 완성 후 UI/UX 판단 기준.
완료 기준:
1. 불편함마다 ID(P1, P2...)가 있고, 누가 언제 왜 힘든지 설명된다.
2. 불편함마다 이번 SW가 해결할 것 / 해결하지 않을 것으로 나뉘고 이유가 있다.
3. As-Is와 To-Be 기본 사례가 끊기지 않고, 담당자 말로 된 행위자와 업무 객체가 GLOSSARY.md에 있다.

- docs/DOMAIN.md 구성은 불편함 / As-Is / To-Be / 해결할 것과 안 할 것 / 담당자 발언이다. 순수한 도메인 스토리만 쓴다. As-Is를 먼저 쓰고, 끝나면 To-Be를 쓴다.
- 라운드마다 완료 기준 1~3의 상태를 한 줄씩 보여 주고, 빈 항목을 채우는 질문만 해. 다 차면 왕복이 남아도 끝내.
- 문장 형식은 "행위자가 업무 객체를 어떻게 한다". 많이 발생하는 기본 사례만 다룬다. 범위는 넓게 시작해서 네가 판단해 좁혀.
- To-Be도 업무 흐름으로만 쓰고 화면, 기술, 알고리즘은 넣지 마. 담당자가 말한 것만 쓰고, 안이 갈리면 2개까지만 둬.
- 문장마다 근거 Q번호를 표시하고, 담당자가 말하지 않은 내용은 [추론]으로 표시해.
- 기준과 숫자는 본문에 넣지 말고 맨 아래 "담당자 발언" 메모에 원문으로만 둬.
- 이번 라운드에는 물을 수 있는 질문 중 결과를 가장 바꾸는 3개만 물어. 전체 왕복은 최대 4번. 완료 기준 1이나 2가 비어 있을 때만 1번 더.
- 담당자 질문은 개발 용어와 추천 답 없이, 그대로 복사해 보낼 문장으로 따로 보여 줘.
- 상한에 도달하면 남은 질문은 [미확인]으로 남기고 끝내. 전부 돌 때까지 계속하지 마.
- 담당자가 지금의 사실을 모른다고 하면 [미확인]으로 두고 다시 묻지 마.
- 담당자가 앞으로의 방식을 "알아서 정하라"거나 "모르겠다"고 하면 다음 질문으로 넘어가지 마. 그 자리에서 선택지 2개와 추천, 이유를 두 줄로 나에게 보여 주고, 내가 고르면 docs/DECISIONS.md에 응시자 결정으로 남겨. DOMAIN.md의 To-Be에는 [응시자 결정 D번호]로 표시해. 화면, 기술, 알고리즘은 고르게 하지 마.
- 끝나면 커밋하기 전에 커밋할 파일과 메시지를 보여 주고 내 확인을 받아. 커밋 대상은 docs/DOMAIN.md, GLOSSARY.md, docs/INTERVIEW.md, docs/DECISIONS.md만이야.
```

## 담당자에게

**Codex의 추천 답은 담당자에게 전달하지 않는다. 답을 유도하게 되니 질문만 보낸다.**

흐름이 정리되면 확인을 받는다.

> 제가 이해한 불편함, 지금의 업무 흐름, 바뀌었으면 하는 흐름, 이번에 해결할 것과 다루지 않을 것입니다. (번호 목록) 틀리거나 빠진 것만 알려 주세요.

## 내가 할 것

빈 단계 채우기 (왕복 최대 4번, As-Is 3번과 To-Be 1번 목표)

| 상황 | 처리 |
|---|---|
| 끊긴 단계 | "그 자료를 받은 다음에는 무엇을 하세요?"처럼 그 단계만 묻는다 |
| 경우의 수가 많음 | "가장 자주 있는 경우로 말씀해 주세요" |
| 기본 사례가 안 잡힘 | 간단한 사례, 보통 사례, 아주 어려운 사례를 묻는다. 어려운 사례는 별도 절에 둔다 |
| 지금의 사실을 모른다는 답 | 다시 묻지 않고 [미확인] |
| 앞으로의 방식을 알아서 정하라는 답 | 그 자리에서 내가 고르고 DECISIONS에 응시자 결정으로 기록 |

## 완료 조건
