# 1단계. 사실 수집과 첫 질문 (10분)

## 목표

수치가 있는 데이터 패턴과 담당자의 첫 답이 남는다. 터미널 A에서 돌려 두고, 2단계를 터미널 B에서 동시에 진행한다. Codex 응답이 많이 느리거나 메모리가 빠듯하면 순서대로 한다.

## Codex에게

```
README와 제공 데이터를 읽고 docs/FACTS.md에 정리해. 나에게 질문하지 말고, 설계나 구현도 하지 마.
제공 데이터가 없으면 2, 3번은 "해당 없음"으로 쓰고, scripts/profile.py는 만들지 마.
1. README의 요구·제약·필수 제출물: 원문 인용
2. 데이터 프로필: 파일별 행 수, 열, 값 범위, 빈 값, 이상치, 파일 간 연결 키
3. 데이터 패턴: 의미 있는 기준으로 나눠 쏠림이나 이상 패턴 3~5개. 수치와 계산 방법 포함
4. 아직 모르는 것: 결과를 바꿀 결정만
사실과 추론을 구분해. 분석 코드는 scripts/profile.py에 남겨.
끝나면 커밋하기 전에 커밋할 파일과 메시지를 보여 주고 내 확인을 받아. 커밋 대상은 docs/FACTS.md와 scripts/profile.py만이야.
```

## 담당자에게

해법을 뜻하는 단어는 쓰지 않는다.

> 지난번에 이 일을 하셨을 때를 처음부터 끝까지 순서대로 말씀해 주실 수 있을까요? 누가 무엇을 받아서 어떻게 넘기는지 궁금합니다. 그때 가장 힘들었던 부분도 알려 주세요.

- 답이 흐리면: "가장 간단했던 경우, 보통인 경우, 아주 어려웠던 경우를 하나씩 말씀해 주세요."
- 새로 만드는 업무라 "지난번"이 어색하면: "지금은 이 일을 어떻게 하고 계신가요?"

## 내가 할 것

- 데이터가 없어 보이면 README의 경로를 먼저 확인하고, 인터뷰 때 담당자에게 예시 자료가 있는지 묻는다.
- 그래도 모른다고 하면 다시 묻지 않는다. 데이터와 3단계 규칙으로 메운다.
- 첫 답을 터미널 B의 인터뷰에 넘긴다.
- 답은 고치지 않고 `docs/INTERVIEW.md`에 Q번호와 함께 원문 그대로 붙인다. 양식: `kit/templates/INTERVIEW.md`

## 완료 조건

- [ ] 담당자 첫 답을 원문으로 기록
- [ ] 코드와 설계 없음
- [ ] 커밋
