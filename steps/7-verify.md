# 7단계. 검증과 제출 (T+150~170)

## 목표

시나리오 결과와 한계가 기록되고 제출한다. 새 기능을 넣지 않는다.

## Codex에게

① 최종 검증 (150~155):

```
마지막 커밋 기준으로 전체 테스트를 실행하고, 수용 시나리오 전부를 점검해 docs/VERIFICATION.md에 기록해. 양식은 kit/templates/VERIFICATION.md.
자동 테스트, 수동 확인, 미실행을 구분해. 0건만 실행된 검사는 통과로 쓰지 마. 실패를 고치지 말고 기록만 해.
내부 함수나 테스트 전용 경로가 아니라 실제 HTTP 요청으로 확인해. 화면은 내가 Browser 미리보기에서 확인해 알려 줄 테니, 내가 알려 준 결과를 수동 확인으로 기록해.
동작과 결과 상태를 함께 기록하고, 저장 결과는 다시 조회해서 확인해.
통과시키려고 시나리오를 약하게 바꾸지 마.
```

수동 확인 시작 전:

```
docs/DOMAIN.md의 To-Be, spec.md의 수용 시나리오, README의 필수 요구를 보고 내가 Browser 미리보기에서 직접 확인할 시나리오 3개를 골라 줘.
핵심 흐름, 담당자가 가장 힘들다고 한 사례, 틀린 입력이나 빈 값 각 1개. 시나리오마다 누를 순서와 기대 결과를 3줄 안으로 써. 네가 서버나 브라우저를 띄우지 마.
```

수동 확인 후:

```
수동 확인 결과: <시나리오 ID와 통과/실패, 실패면 본 현상>
docs/VERIFICATION.md에 수동 확인으로 그대로 기록해. 코드는 고치지 마.
```

② 달라진 점 찾기 (155~160):

```
INTERVIEW.md의 합의, DOMAIN.md의 해결할 것과 To-Be, spec.md, 실제 코드를 비교해 네가 판단해서 바꾸거나 빠뜨린 것을 전부 나열해. 테스트로 고정한 결정도 포함해.
```

③ 제출 문서 (160~165):

```
docs/LIMITATIONS.md를 30줄 이내로 작성. 6개 영역에서 각 1개, 심각도 순:
①합의와 달라진 결정 ②입력·데이터 예외 ③핵심 로직 경계 ④테스트가 못 잡는 것 ⑤유지보수·운영 ⑥AI 판단의 근거.
항목마다 약점 / 위험과 파급 / 다음 검증, 근거 파일:줄 표시. 확인되지 않은 내용은 쓰지 마.
```

④ 내 머리에 넣기 (165~170):

```
다음을 각 3줄로 설명해. 파일 저장은 하지 마.
1. 입력부터 화면까지 데이터 흐름과 상태 소유
2. 핵심 알고리즘의 동작과 가장 약한 입력
3. 데이터나 조건이 바뀌면 먼저 깨지는 곳
```

## 내가 할 것

- ①: 마지막 커밋 기준으로 실행 환경을 새로 띄워 `docs/DOMAIN.md`의 To-Be 순서대로 화면을 직접 눌러 본다.
- ①: 시간이 남으면 새로고침 후 저장 결과와 README 필수 요구를 확인한다.
- ②: 하나씩 고치거나, 승인하거나, 한계로 넘긴다.
- ③: README 끝에 "평가자가 볼 곳": 실행 명령과 주소, 핵심 파일 3개, 직접 해 볼 시나리오 3개와 기대 결과, 미검증 항목.
- ③: `docs/AI_LOG.md`가 실제 기록인지 확인한다.
- ③: README가 정한 필수 파일과 경로를 확인한다.
- ④: 핵심 결정 2~3개에 머릿속으로 네 칸을 채운다: 선택 → 약점 → 위험 → 다음 검증.
