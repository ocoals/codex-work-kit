# 4단계. 합의 (10분)

## 목표

숫자와 확인 방법까지 담은 담당자의 답이 `INTERVIEW.md`에 원문으로 남는다.

## Codex에게

```
FACTS.md, DOMAIN.md, DECISIONS.md를 근거로 담당자에게 보낼 합의문을 15줄 이내로 작성해.
기술 용어 없이 쓰고, 파일에 저장하지 말고 먼저 나에게 보여 줘.
1. 해결할 문제: DOMAIN.md의 불편함 ID 표시
2. 만들 것 / 이번에 안 만들 것: 불편함 ID와 연결
3. 기준: 담당자 확정은 숫자까지, 운영자 조정값은 기본값과 조정 가능 여부
4. 성공 판단: 숫자와 확인 방법
5. 이번 결과의 한계
보여 주기 전에 스스로 점검해: 숫자의 출처가 DECISIONS.md와 맞는지, 담당자가 말하지 않은 내용은 "제안, 확인 필요"로 표시했는지, 성공 판단에 숫자와 확인 방법이 있는지, 기술 용어가 없는지.
```

## 담당자에게

보내기 전에 "만들 것 / 이번에 안 만들 것"과 내가 정한 항목만 내 판단과 맞는지 본다. 나머지 점검은 Codex가 한다.

> 제가 이해한 내용으로 이렇게 진행하려고 합니다. (합의문) 틀리거나 빠진 부분이 있으면 알려 주세요. 특히 3번 기준과 4번 성공 판단이 업무에 맞는지 봐 주세요.

## 내가 할 것

| 담당자의 답 | 처리 |
|---|---|
| 동의 | 원문을 기록하고 완료 |
| 일부 수정 | DECISIONS와 합의문을 고치고 바뀐 부분만 확인 |
| 모호함 | 내 이해를 명시하고 "이 내용으로 진행하겠습니다"라고 알린 뒤 진행 |
| 새 요구 | 과제 README의 필수이거나 성공 기준을 바꾸면 포함하고 다른 범위를 줄인다. 있으면 좋은 정도면 범위 밖으로 두고 이유를 담당자에게 알린 뒤 기록한다 |

합의문과 답은 `INTERVIEW.md`에 원문으로 남긴다. 별도 파일은 README가 요구할 때만 만든다.
