# 5단계. 명세와 티켓 (15분, effort medium)

## 목표

숫자 시나리오가 있는 명세, 티켓 3~4장, `docs/HANDOFF.md`가 남는다.

## Codex에게

명세:

```
$to-spec
INTERVIEW.md, FACTS.md, DOMAIN.md, DECISIONS.md를 근거로 docs/<feature>/spec.md를 작성해.
1. 문제와 성공 기준: 담당자 합의 Q번호 표시
2. 업무 객체와 흐름: 업무 객체→데이터, 활동→상태 변화, 행위자→화면
3. 결정과 대안: DECISIONS는 ID로 참조, 핵심 결정의 이유만 설명
4. 기본 사례 밖의 경우: 지원 / 운영자 조정값 / 범위 밖
5. 가정: 담당자 미확인 항목과 틀렸을 때의 영향
6. 수용 시나리오: 간단·보통·어려운 사례 각 2개 이상. ID, 입력 숫자, 기대 결과
7. 유저스토리와 기능 목록: DOMAIN.md의 해결할 불편함 ID별로 쓰고, 기능마다 수용 시나리오 ID를 연결. 불편함과 연결되지 않는 기능은 넣지 마
근거 없는 결정은 5번으로 보내. 합의에 없는 기능은 넣지 마.
```

ADR (핵심 알고리즘이 있을 때):

```
DECISIONS.md의 방법 수준 결정을 docs/adr/0001-<결정>.md로 작성해.
목적과 제약, 규모 / 후보 2~3개 / 고른 이유 / 버린 이유 / 알려진 한계 / 방법을 바꿀 조건.
내가 정한 결정은 바꾸지 말고, 반대 근거가 있으면 따로 알려 줘.
```

티켓:

```
$to-tickets
spec.md를 세로로 자른 티켓 3~4장으로 나눠. docs/<feature>/issues/NN-<slug>.md.
각 티켓에 우선순위(필수/있으면 좋음), Blocked by, 담당 수용 시나리오 ID, 세션 하나로 끝날 크기를 적어.
01번은 입력 하나가 화면까지 가는 가장 얇은 흐름을 실제 실행 환경에서 띄우는 티켓으로 해.
모든 수용 시나리오가 어느 티켓엔가 들어가게 해.
```

AGENTS.md:

```
$writing-for-agents
"작업 규칙"과 "환경 규칙" 절은 그대로 두고, AGENTS.md의 나머지를 30줄 이내의 지도로 정리해. 문서 위치, 실행·테스트 명령, 저장소 규칙만 남겨.
코드에서 알 수 있는 내용과 명세를 옮겨 적은 내용은 빼.
```

세션 닫기. 커밋 후 실행하고, 이 파일까지 커밋한 뒤 세션을 닫는다.

```
$handoff docs/HANDOFF.md에 저장. 다음 세션은 티켓 01 구현부터 시작한다.
```

## 내가 할 것

명세가 나오면 3분 검수한다.

- [ ] 합의의 숫자와 범위가 그대로 있는가
- [ ] 합의에 없는 기능이 없는가
- [ ] 모든 기능이 해결할 불편함과 연결되는가
- [ ] 내 조건과 담당자 조건이 섞이지 않았는가
- [ ] 수용 시나리오가 숫자로 판단되는가

## 완료 조건

- [ ] 명세 3분 검수
- [ ] 티켓 3~4장
- [ ] HANDOFF까지 커밋하고 세션 닫기

## 시간 초과

T+80을 넘기면 검수만 하고 티켓을 필수 위주로 줄여 넘어간다.
