# 3단계. 결정 표 (15분)

## 목표

미정이 0개인 `docs/DECISIONS.md`가 남고, 방법 수준은 내가 정한다.

## Codex에게

새 세션에서 시작한다. 터미널 A와 B의 세션은 닫는다. 앞 단계 내용은 파일에 있다.

```
$grill-with-docs
FACTS.md, DOMAIN.md, INTERVIEW.md로 docs/DECISIONS.md를 만들어. 이미 있는 응시자 결정은 유지해. 양식은 kit/templates/DECISIONS.md.
상태: 담당자 확정 / 데이터 확인 / 운영자 조정값 / 응시자 결정 / 가정 / 미정. 처음에는 미정 또는 가정.
1. 답에 따라 결과가 달라지는 결정만 미정. 나머지는 추천안대로 하고 가정.
2. 담당자가 말한 숫자는 제약 / 선호 / 근거 부족으로 나누고, 데이터 대조 수치를 근거에 적어.
3. 서로 부딪히는 요구는 하나의 결정으로 묶고, 선택지별 득실을 적어.
4. 핵심 방법은 네가 정하지 말고 선택지와 규모 근거만 적어.
5. 이번 라운드에는 물을 수 있는 질문 중 결과를 가장 바꾸는 4개만, 현장 말로, 선택지를 붙여 물어. 왕복은 최대 2번.
   상한에 도달하면 남은 항목은 추천안대로 가정으로 두고 끝내. 전부 돌 때까지 계속하지 마.
6. 상태가 정해진 항목은 다시 묻지 마.
7. 표의 "정할 사람" 칸에 담당자 / 나 / Codex를 적어. 담당자: 업무 우선순위와 현장 규칙. 나: 핵심 방법과 담당자가 맡긴 결정. Codex: 틀려도 쉽게 고칠 수 있는 가정.
8. 담당자 질문은 개발 용어와 추천 답 없이, 그대로 복사해 보낼 문장으로 따로 보여 줘.
```

Codex의 가정은 한꺼번에 승인한다:

```
상태가 가정인 항목을 표로 보여 줘. 결과를 크게 바꾸는 것을 위에 놓아.
나는 "A3 ✘ 이유"처럼 거절할 항목만 답한다. 답하지 않은 항목은 승인으로 처리해.
```

## 담당자에게

**Codex의 추천 답은 담당자에게 전달하지 않는다. 답을 유도하게 되니 질문만 보낸다.**

왕복 최대 2번.

- 나쁜 예: "목적함수 가중치는?"
- 좋은 예: "비용을 10% 줄이는 것과 처리 시간이 10분 느는 것 중 어느 쪽이 더 문제인가요?"
- 반대하는 쪽도 묻는다: "이 결정에 반대할 분이 있다면 어느 부서이고, 어느 정도면 받아들일까요?"
- 명확한 답은 담당자 확정. 모호한 답은 선택지를 좁혀 한 번만 다시 묻는다. 또 모호하면 내가 결정한다.

## 내가 할 것

담당자 숫자 대조:

| 대조 결과 | 처리 |
|---|---|
| 데이터와 맞고, 어기면 안 되는 조건 | 제약 |
| 대체로 맞지만 예외가 있음 | 선호로 두고 점수에 반영 |
| 넣어 보니 결과가 무너짐 | 담당자에게 수치를 보여 주고 다시 확인 |
| 데이터로 확인 불가 | 근거 부족 |

남은 것 처리:

- 못 정한 트레이드오프: 운영자 조정값으로 만들고 기본값을 둔다. 바꿨을 때의 결과를 보여 준다.
- 방법 수준은 내가 정해서 남긴다: "응시자 결정: 입력 규모 N, 응답 시간 M초 조건이므로 A를 쓴다. B는 검증 시간 안에 끝내기 어려워 버린다. 작은 샘플로 B와 격차를 비교한다."
